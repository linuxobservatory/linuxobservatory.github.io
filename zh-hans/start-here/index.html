刚接触 Linux 游戏？
这里欢迎你。

你不需要熟悉 Linux、会组装电脑或读懂性能图表，也能跟随这些实验。从一个游戏、一个问题和一个数字开始。

15 秒解释

什么是 Linux Observatory？

想象有人在 Linux 电脑上运行游戏，并在屏幕上保留几项性能读数。他们不只是说“能运行”或“跑得快”，而是录下实际发生的情况。

这就是 Linux Observatory：一个独立运营的项目，由 Ediz Iniziel 在有记录的条件下运行游戏，录制连续实况，并公开观察记录供人查验。

它并不承诺每台电脑都会有相同表现，而是为某一次真实运行提供一个背景明确的观察窗口。

你的第一段录像

值得注意的三件事。

01 / 画面

观察游戏

能运行吗？动作看起来流畅吗？有没有异常画面或停顿？你的眼睛也是有用的观察工具。

02 / 角落

观察数值

叠加层可能显示 FPS、帧时间、GPU 使用率和内存。这些是线索，而不是用来比拼的分数。

03 / 背景

阅读运行条件

留意游戏、分辨率、GPU、Proton 版本和 Mesa 驱动。缺少背景时，性能数字可能产生误导。

你会看到的四个术语

一本小小的 Linux 游戏词典。

Linux

一种像 Windows 或 macOS 一样让电脑运行的操作系统。Linux 有许多发行版，包括 Fedora。

Proton

与 Steam 配合使用的兼容工具，帮助许多 Windows 游戏在 Linux 上运行。它不是对整台 Windows 电脑的模拟。

FPS

Frames per second，即每秒帧数：游戏在一秒内产生多少幅图像。更高可能更好，但稳定一致也很重要。

MangoHud

屏幕上的性能叠加层。在游戏运行时，为观众显示有用的数值。

RADV

适用于许多 AMD 显卡的 Vulkan 驱动，是 Mesa 图形项目的一部分。

Frame time（帧时间）

一帧需要的时间。异常长的帧往往能帮助解释平均 FPS 读数掩盖的卡顿。

尝试一个实验

为什么有人要在 16K 下测试游戏？

不是因为这种分辨率对大多数人实用。极端负载可以揭示内存分配、渲染、驱动行为及应用限制在压力下的反应。

这有点像给桥梁施加重载来观察表现：测试关注的是系统如何响应，而不是建议日常这样使用。

这个类比有局限。一次游戏运行并不是经过认证的工程载荷测试，一次失败也无法确定精确的瓶颈。

METHODOLOGY / HOW A RECORD IS MADE

Observe.
Instrument.
Record. Inspect.

Continuous observation is the starting point. A comparison needs stricter controls; a diagnosis needs tested explanations. Those activities are related, not interchangeable.

01 / OBSERVE

Choose the question

A game, a graphics-stack change, a native-versus-Proton run, a specific failure, or an unusual workload.

02 / INSTRUMENT

Make behavior visible

Use performance overlays when appropriate, while acknowledging sampling limits and instrumentation overhead.

03 / RECORD

Preserve the run

Capture the visible experience and measurements together. Where footage is continuous, the viewer can inspect the sequence rather than only a summary.

04 / INSPECT

Interpret carefully

Separate what appeared on screen from hypotheses about why it happened. A frame-time spike is an observation; its root cause needs investigation.

THREE TYPES OF EVIDENCE

Not every test makes the same claim.

TIER 01

Observation

Gameplay recorded under stated conditions. Valid for showing what happened in that run. Not enough by itself for universal performance claims.

TIER 02

Comparison

Runs with comparable workloads, controlled variables and repeated measurement where possible. Stronger for differences between configurations.

TIER 03

Diagnostic

A targeted investigation of an observed fault using symptoms, hypotheses, tests and findings. Stronger for identifying a cause.

An important limitation

Earlier recordings do not necessarily contain every metadata field used in newer documentation. Missing context must be marked rather than reconstructed as fact. The original footage can still document what visibly happened.

Suggested minimum description for a new observation

TYPE: Observation
GAME: [title / build]
DATE: [YYYY-MM-DD]
GPU / CPU: [models]
DISTRO / KERNEL: [versions]
MESA / DRIVER: [version or package provenance]
RUNTIME: [Linux native / Proton build / other]
RENDERING: [game resolution, output resolution, VSR/Gamescope]
SETTINGS: [relevant graphics settings]
INSTRUMENTATION: [overlay and mode]
WHAT WAS OBSERVED: [descriptive, not causal]
KNOWN LIMITATIONS: [missing data, possible confounds]

A controlled comparison requires additional fields: workload matching, repeat count, measurement method, variability and results. A diagnostic entry requires hypotheses and tests.
